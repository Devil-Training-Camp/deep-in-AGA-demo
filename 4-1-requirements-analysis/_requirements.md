# AI 知识问答系统 · 需求文档

> 本文档只回答"做什么",不涉及任何技术实现。判据:非技术背景的产品经理能读懂。

## 1. 一句话概述

团队成员上传文档后,可以用自然语言对文档内容提问,系统返回基于文档的回答,支持流式输出和多轮追问。

## 2. 用户角色与用户故事

系统面向**团队**使用,同一团队共享同一批文档。成员在使用中承担两种角色,同一个人可以既是上传者也是提问者。

- **上传者**:向系统上传文档,使其可被团队提问。
  - 作为上传者,我希望上传文档后它立即对全团队可见,这样其他成员无需重复上传就能提问。
- **提问者**:对已上传的文档用自然语言提问,获取答案。
  - 作为提问者,我希望用日常语言提问而不必猜关键词,这样能快速拿到文档里的信息。
  - 作为提问者,我希望能就同一话题连续追问,系统记得我们刚才聊到哪里,这样不必每轮都把背景重说一遍。

## 3. 功能列表(含验收条件)

### 3.1 文档上传

支持上传纯文本类文档(以 .txt、.md 为主),上传后进入团队共享范围。

**验收条件**
- 支持上传 .txt、.md 格式文件,上传成功后在文档列表中可见。
- 上传的文档默认对全团队所有成员可见,任意成员都能对其提问。
- 上传的文档格式不受支持时,提示具体原因(如"暂不支持该格式"),而非泛化的失败提示。
- 上传失败时(如文件损坏、超出大小限制),显示具体错误原因,用户据此可判断下一步怎么做。

### 3.2 基于文档的问答

用户用自然语言提问,系统基于团队已上传的文档内容生成回答。

**验收条件**
- 回答以文档内容为主要依据。
- 文档中确实没有相关内容时,允许结合模型自身知识补充作答,但补充部分必须明确标注"此部分非文档内容",让用户能区分依据来源。
- 回答不要求标注具体出处(不指明来自文档的哪一章节或段落),直接返回整合后的答案。

### 3.3 流式输出

回答以流式方式逐步呈现,而非等全部生成完再一次性显示。

**验收条件**
- 提问后,回答内容逐步显示(打字机式呈现),而非长时间空白后整段弹出。
- 首字节延迟(从提问到看见第一个字)不超过 3 秒。

### 3.4 多轮追问

同一会话内支持连续追问,系统记住上下文,能理解跨轮次的指代。

**验收条件**
- 系统记住当前会话的历史问答,后续提问能理解"它 / 这个 / 上面提到的"这类指代,无需用户重复背景。
- 用户主动新建对话时,清空上下文,重新开始一段独立会话。
- 会话在无操作达到超时阈值(默认 30 分钟)后自动结束,上下文清空;此后再提问按新会话处理。

## 4. 边界声明(不做什么)

- **不支持复杂格式文档**:PDF、Word、Excel、图片、扫描件等不在本期范围;只处理纯文本类内容(.txt、.md 为主),不做排版还原、表格识别、OCR。
- **不做文档库跨文档综合检索的高级形态**:本期以团队共享的文档集合为提问范围,不承诺检索排序、相关度打分等检索系统级能力。
- **不做对话历史的长期留存**:会话上下文仅当次有效,新建对话或超时即清空;不提供历史对话的持久保存、回看、恢复。
- **不做细粒度权限与共享控制**:文档上传即全团队可见,不提供"仅自己可见""指定成员可见""按角色授权"等私有或分级共享能力。
- **不标注回答出处**:不提供引用定位、原文片段回跳等溯源功能。
- **不做多语言 / 跨语言问答的专门保障**:本期不承诺文档与提问跨语种时的问答质量。

## 5. 风险点(交后续架构阶段规避)

- **文档依据与模型补充难以分辨**:已确定"以文档为主、可补充",且补充部分要标注"非文档内容";但同时又不标注具体出处。两条叠加后,用户可能仍难以判断某句回答究竟来自文档还是模型补充,存在被误导的风险。需在后续阶段明确"标注非文档内容"这一提示的呈现方式,确保它足够醒目、不被忽略。
- **回答可信度的验收缺口**:目前对"回答是否忠于文档"没有可量化的验收标准(如答对率、编造率)。这类质量标准需要在后续阶段补充评测方式,否则"以文档为主"只是主观描述。
- **超时阈值的合理性未验证**:30 分钟为拍脑袋的默认值,是否符合团队真实使用节奏未经验证,后续可能需要根据实际场景调整。
- **共享范围过宽的隐性风险**:上传即全团队可见,意味着任何敏感文档一旦上传就无法限制查看范围。当前作为边界明确排除,但需确认这符合团队对文档敏感度的预期。
