# 项目概览

AI 知识问答系统：用户上传文档，对文档内容提问，系统返回基于文档的回答，支持流式输出和多轮对话。

本 demo 对应课程 4.1「需求分析」，目标是在写任何代码、做任何技术决策之前，先用 `/prd` Skill 把需求推演清楚，产出一份可驱动开发的 `requirements.md`。

## 需求文档约束

生成或修改 `requirements.md` 时，严格遵守以下约束：

- **只回答"做什么"，不涉及"怎么做"**。禁止出现架构、技术栈、数据库、框架等实现细节（如"用 pgvector 存向量""前端用 React Query"）。判据：非技术背景的产品经理读得懂，就是需求；读不懂，就是方案。
- **只覆盖四类内容**：用户角色与用户故事、带验收条件的功能列表、边界声明（不做什么）、风险点。与这四类无关的问题不追问，尤其不追问技术实现细节。
- **每条功能必须附验收条件**，说清"怎么算完成"（如"首字节延迟不超过 3 秒""失败时显示具体错误原因"），没有验收标准的条目不通过。
- **边界声明写清"不做什么"**，防止范围被悄悄扩大。
- **风险点登记未想清楚的不确定性**，交给后续架构阶段规避。

## 产出物

- `requirements.md`：本 demo 的唯一产出，路径在项目根目录。
